## 核心架构模式

### 1. 多智能体协作模式

```
用户输入
    ↓
┌─────────┐
│ 大纲师  │ ← 网文拆解知识库
└────┬────┘
     ↓
┌─────────┐     ┌─────────┐
│ 码字工  │ ←──→ │  督察   │ (最多3次重试)
└────┬────┘     └─────────┘
     ↓
┌─────────┐
│  运营   │
└────┬────┘
     ↓
输出章节
```

### 2. 分层记忆架构

```
┌─────────────────────────────────────┐
│ 层级0: 故事Bible (静态)            │ ← 全局约束
├─────────────────────────────────────┤
│ 层级1: 人物档案 (动态)             │ ← 每章更新
├─────────────────────────────────────┤
│ 层级2: 大事记 (追加)               │ ← 事件记录
├─────────────────────────────────────┤
│ 层级3: 最近N章 (滚动)              │ ← 局部上下文
├─────────────────────────────────────┤
│ 层级4: 钩子清单 (状态机)           │ ← 悬念追踪
└─────────────────────────────────────┘
```

### 3. RAG检索增强流程

```
写作请求
    ↓
┌─────────────────┐
│ 分析章节需求    │
└────────┬────────┘
         ↓
┌─────────────────┐
│ 向量检索相关    │ ← ChromaDB

└────────┬────────┘
         ↓

         ↓
```

## 数据流

### 写作流程数据流

```
1. 用户输入创意
   ↓
2. 大纲师生成StoryBible
   - 世界观设定
   - 人物设定
   - 章节细纲
   ↓
3. 写作前准备
   - 从向量库检索相关角色
   - 从缓存加载最近章节
   - 从记忆系统加载钩子/事件
   ↓
4. 码字工生成章节
   - 使用RAG上下文
   - 遵循细纲
   - 埋设新钩子
   ↓
5. 督察审核（12项检查）
   - 时空一致性
   - 性格一致性
   - 能力体系
   - ...
   ↓
6. 运营润色
   - 优化标题
   - 增强表达
   ↓
7. 数据持久化
   - 保存章节
   - 更新人物状态
   - 更新钩子状态
   - 更新大事记
   - 索引到向量库
```

## 性能瓶颈与优化

### 潜在瓶颈

1. **LLM调用延迟** - 每章生成需要多次LLM调用
2. **向量检索性能** - 大量文档时检索变慢
3. **内存占用** - 缓存和向量数据占用内存

### 优化策略

1. **LLM调用**
   - 使用流式输出减少感知延迟
   - 缓存常见Prompt的响应
   - 批量处理非关键任务

2. **向量检索**
   - 使用本地ChromaDB避免网络延迟
   - 定期清理过期索引
   - 限制检索结果数量

3. **内存管理**
   - LRU缓存自动淘汰
   - 限制缓存大小
   - 定期清理过期数据

## 安全考虑

1. **API密钥** - 存储在.env文件，不提交到代码库
2. **数据隐私** - 本地存储，不上传到云端
3. **内容审核** - 督察智能体检查敏感内容
4. **输入验证** - 验证用户输入，防止注入攻击
